# Шаблон кафе «Соль»

Адаптивный React/Vite-шаблон: главная `/` и отдельное меню `/menu`. Поиск, категории, фильтр без мяса и рыбы, корзина навынос, TXT списка, галерея с увеличением, FAQ и пожелания к бронированию. Это демонстрация вымышленного заведения, фотографии сгенерированы. Источники и лицензии: ASSETS.md.

Установка: `pnpm install` или `npm install`. Запуск: `pnpm dev` или `npm run dev`. Сборка: `pnpm build` или `npm run build`. Проверка совместимости с Sites: `pnpm test:sites`.

Содержание редактируется в `src/content.json`: название, метаданные, строки заголовка, меню, цены, фотографии, цвета, часы, контакты и включение разделов. Файлы изображений — `public/images`, оформление — `src/styles.css`, структура и стандартные подписи — `src/App.jsx`.

Новый клиентский проект: `node tools/create-cafe.mjs --slug new-cafe --name "Название кафе"`. Он появится в соседней папке `clients/new-cafe`. Исходный проект не меняется, существующая папка не перезаписывается, project_id и рабочие данные не копируются.

Перед публикацией заполнить реальные контакты, проверить все цены и состав, заменить фото и alt-тексты, выбрать `booking.mode: "external"` и URL настоящего сервиса брони, удалить демотексты, затем выставить `demo: false`. Проверка при сборке требует внешний сервис и контакты для реального режима. Поле `times` — примеры времени демоформы, не фактическая доступность.

Демоформы не отправляют данные. Корзина сохраняется в памяти при внутренних переходах, при перезагрузке очищается. TXT содержит введённые контакты. Для реального навыноса задать `pickup.mode: "external"` и `pickup.url` либо отключить раздел; локальная корзина автоматически в сервис не переносится. Флаги vegetarian и сведения о составе подтверждает клиент. Полноценные сервер брони, CMS, доставка и оплата не подключены. Для статического хостинга нужен fallback клиентских маршрутов на index.html; встроенный Worker его поддерживает. Публикация и домен настраиваются отдельно. `npm run build` сам по себе ничего не публикует.

Подробный бриф и исследование сохранены рядом с исходным шаблоном; у каждого клиента нужен собственный браузерный отчёт проверки.
